Commit message generation through a terminal agent

2026-10-11 and 2026-10-17. 60 real commits of openai/codex and JetBrains/intellij-community, diff from 0.4 KB to 102.0 KB, 1 runs per commit and agent. Cheap models only. Claude Code 2.1.291, codex-cli 0.154.0, codex-acp 2.2.2, claude-agent-acp 0.89.1, Junie 26.10.5, OpenCode 1.19.3, macOS.

Verdict

Use the CLI mode, not ACPclaude -p and codex exec give the message in 2–3 seconds for less than 2 cents. The IDE collects the diff and gives it to the agent; the agent only writes text.
Claude Code and Codex are readyAll runs succeeded and the output was clean text. Haiku 4.5 is the fastest; Haiku 5.5 writes the best explanations; Luna writes short and exact messages.
OpenCode works over ACPThe client starts opencode acp with our agent in the environment: our system prompt, no tools, no title call. 2.9 s per message with Luna, 1.0 s of it the start of the process.
Junie is not suitable todayIts CLI returns a task report instead of the message and makes several model calls. Its ACP mode needs the IDE for authorization.
Do not trust issue ids from the model25 of the 90 ids that the models wrote were wrong. The IDE takes the id from the branch name only.
