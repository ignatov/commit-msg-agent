Commit message generation through a terminal agent

2026-10-11. 8 real commits of openai/codex and JetBrains/intellij-community, diff from 0.6 KB to 51.1 KB, 2 runs per commit and agent. Cheap models only. Claude Code 2.1.291, codex-cli 0.154.0, codex-acp 2.2.2, claude-agent-acp 0.89.1, Junie 26.10.5, macOS.

Verdict

Use the CLI mode, not ACPclaude -p and codex exec give the message in 2–3 seconds for less than 2 cents. The IDE collects the diff and gives it to the agent; the agent only writes text.
Claude Code and Codex are readyAll runs succeeded and the output was clean text. Haiku 4.5 is the fastest; Haiku 5.5 writes the best explanations; Luna writes short and exact messages.
Junie is not suitable todayIts CLI returns a task report instead of the message and makes 6–9 model calls. Its ACP mode needs the IDE for authorization.
Do not trust issue ids from the modelModels copy an unrelated id from the history or invent one in about half of the cases. The IDE takes the id from the branch name only.

Issue ids are already removed: these commits have no branch name.

What the integration needs

  • The diff of the changes that the user selected in the commit dialog, the recent commit messages of the same files, and the branch name. The IDE builds this; the git index is not the same as the selection.
  • Special switches for each agent: without them a call is 10× more expensive, up to 30 s slower, and user settings (hooks, plugins, memory files) can put foreign text into the message.
  • A version check of the CLI: the switches exist only in current versions.

Not checked

  • Windows and Linux.
  • A Claude subscription login; the tests used an API key helper.
  • Junie with a JetBrains AI subscription, and Junie ACP inside the running IDE.
