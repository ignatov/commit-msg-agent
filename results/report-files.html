Commit message generation: the diff in the prompt or the files for the agent

2026-10-17. 70 real commits of openai/codex and JetBrains/intellij-community, diff from 0.4 KB to 994.2 KB, one run per commit and config. Quality: scores of a judge model, Claude Opus 5.5. Claude Code 2.1.291, codex-cli 0.154.0, macOS.

Two ways to give the change to the agent

DiffThe IDE puts the diff into the prompt, at most 60k characters. The agent has no tools and only writes text. This is the default of the prototype.
FilesThe prompt lists the changed files. The agent runs git diff --cached in the repository itself and reads what it needs, with read-only tools.

Both prompts hold the list of the changed files, the recent commit subjects of the same files, and the branch.

Verdict

⏱ The files mode is slower at every size.The agent makes at least one more model call to read the diff: +1.9 s for Haiku 5.5 and +2.3 s for Luna on a commit under 5 KB, +4.3 s and +6.1 s over 60 KB.
✅ It helps Claude on large commits.Over 60 KB, where the diff mode cuts the diff, the mean score goes from 3.62 to 4.23 for Haiku 4.5 and from 3.77 to 4.15 for Haiku 5.5. Luna gains nothing: 4.00 to 4.08.
✅ Haiku 5.5 writes better messages at every size.4.29 to 4.64, better on 21 commits and worse on 9. In the files mode it thinks before the answer in 45 of 70 messages, in the diff mode in 3. A higher effort in the diff mode can give the same without the tools: not tested.
❌ Haiku 4.5 is too slow for the files mode.4.1 tool calls per message, p90 30.2 s, the slowest 86.4 s.
🟡 For the IDE.Keep the diff mode, and switch to the files mode when the diff does not fit the budget: 13 of the 70 commits here. With Haiku 5.5 the files mode can also be the default: 4.4 s instead of 2.1 s for better messages.

How the files mode works

  • The agent works in a clone of the repository in the state just before the commit, with the changes staged. The clone has no refs and no reflog, so the agent cannot find the real message.
  • Claude Code gets Bash, Read, Grep, and Glob in the dontAsk permission mode: it runs the commands that it knows as read-only and denies the rest. Codex gets its shell in the read-only sandbox.
  • The answer goes between <commit_message> tags: after the tool calls Haiku 4.5 writes its notes around the message.
  • Claude Code has two traps in a large repository. A sparse index adds 4 s to every start. dontAsk denies git diff --cached --relative, and then Haiku 5.5 gives up instead of writing the message.

Not checked

  • The diff mode with a higher effort for Haiku 5.5: in the files mode it thinks more often, and that can be the reason for its better messages.
  • Junie and the ACP agents in the files mode.
  • A selection in the commit dialog that is not the git index. Windows and Linux.
