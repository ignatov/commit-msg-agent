# Commit message generation: the diff in the prompt or the files for the agent

Two ways to give the change to the agent:

- **diff**, the default of this repository: the prompt holds the diff, at most 60k characters. The agent has no tools and runs in an empty directory.
- **files**: the prompt holds the list of the changed files (the `--stat`), and the agent runs `git diff --cached` itself and reads what it needs. It runs in the repository with read-only tools.

Both prompts hold the `--stat`, the recent commit subjects of the same files, and the branch.

> 70 real commits of [openai/codex](https://github.com/openai/codex) and [JetBrains/intellij-community](https://github.com/JetBrains/intellij-community), diff from 0.4 KB to 994.2 KB, one run per commit and config, 2026-10-17. The judge scored 70 commits.

Quality: the mean score of the judge from 1 to 5, see [the judge](REPORT-FILES.md#the-judge). ¹ Claude Code 2.1.291 does not know the price of Haiku 5.5. ² The CLI reports tokens, not a price. Input tokens: the sum over all model calls of one message, with the cached tokens.

- ⏱ **The files mode is slower at every size.** The agent makes at least one more model call to read the diff: +1.9 s for Haiku 5.5 and +2.3 s for Luna on a commit under 5 KB, +4.3 s and +6.1 s over 60 KB.
- ✅ **Haiku 5.5 writes better messages, most of all on small commits:** 4.29 to 4.64, better on 21 commits and worse on 9 (p = 0.04), under 5 KB 9 better and 1 worse. Both modes see the whole diff of a small commit, but in the files mode the model thinks before the answer: in 45 of 70 messages, in the diff mode in 3. A higher effort in the diff mode can give the same without the tools: not tested.
- 🟡 **Large commits: a hint, not a result.** Over 60 KB the mean score goes from 3.62 to 4.23 for Haiku 4.5 and from 3.77 to 4.15 for Haiku 5.5, but per commit it is 6 better and 1 worse for Haiku 4.5 (p = 0.13) and 5 better and 4 worse for Haiku 5.5. 13 commits are too few.
- ❌ **Haiku 4.5 and Luna gain nothing.** Per commit 24 better and 18 worse for Haiku 4.5 (p = 0.44), 13 and 17 for Luna (p = 0.58). Haiku 4.5 also makes 4.1 tool calls per message: p90 30.2 s, the slowest 86.4 s.
- 🟡 **For the IDE:** keep the diff mode. With Haiku 5.5 the files mode gives better messages for 4.4 s instead of 2.1 s; a higher effort in the diff mode may give them for less, and needs a check first. Commits over the diff budget need a larger sample.

## How the agents use the tools

- Haiku 4.5: one call or less in 21 of 70 messages, at most 16 calls; read files beyond the diff in 7, ran `git log` in 41; had text outside the tags in 69; a denied call in 1 of the 35 intellij-community messages.
- Haiku 5.5: one call or less in 53 of 70 messages, at most 3 calls; read files beyond the diff in 0, ran `git log` in 0; had text outside the tags in 0; a denied call in 0 of the 35 intellij-community messages.
- Luna: one call or less in 37 of 70 messages, at most 5 calls; read files beyond the diff in 0, ran `git log` in 2; had text outside the tags in 19.

Where the time of Claude Code goes, the medians per message. The rest is the start of the CLI and the tool calls:

- Haiku 4.5: diff 1.7 s in the model calls and 1.1 s in the rest; files 7.1 s in the model calls and 1.9 s in the rest.
- Haiku 5.5: diff 1.3 s in the model calls and 0.8 s in the rest; files 2.9 s in the model calls and 1.7 s in the rest.

## The judge

[`judge.ts`](judge.ts) gives Claude Opus 5.5 one commit at a time: the message of its author, the full `--stat`, up to 400k characters of the diff, and the six messages without their config names, in a shuffled order. It scores each message from 1 to 5 on one question: does the message tell a reviewer correctly what the commit does? The rules tell it to ignore the style, the length, and the issue ids.

One judge and one run per commit: a difference of 0.1–0.2 in the mean score is noise.

## How the files mode works

- **A clone per repository**, [`src/sandbox.ts`](src/sandbox.ts): HEAD is the parent of the commit, and the changes of the commit are staged. The clone has no refs and no reflog, so the agent cannot find the commit and its real message, also not with `git log --all`. Once Haiku 4.5 wrote the real pull request number of codex-35, #38275: `git log` showed #38274 as the last commit, and the model took the next number.
- **intellij-community runs in a large working copy:** a sparse checkout of `community/` with about 340 000 files. `diff.relative=true` gives `git diff` the paths of the public repository. `git status` takes 2.4 s there.
- **The monorepo has two traps, and the intellij-community half ran three times.** With a sparse index every start of Claude Code took 4 s more: at its start Claude Code runs `git ls-files -- ':(icase).claude/settings.local.json'`, and that expands the index. Then Claude Code denied `git diff --cached --relative`, the command that the prompt named: Haiku 5.5 gave up on 14 of the 35 commits, and Haiku 4.5 searched for other ways to the diff. The tables show the third run, with a full index and `diff.relative`.
- **Claude Code** gets `--tools Bash,Read,Grep,Glob --permission-mode dontAsk`. In this mode Claude Code runs the read-only commands and denies the rest, for example `touch` and `git commit`. `--setting-sources user` skips the settings of the repository, so its allow rules cannot permit a write.
- **Codex** gets its shell back. The commands run in the `read-only` sandbox.
- **The answer is between `<commit_message>` tags.** After the tool calls Haiku 4.5 writes its notes before the message: 69 of its 70 answers had text outside the tags. A plain text answer would not be usable.
- **No `Co-Authored-By` trailer.** With the Bash tool, Claude Code tells the model to end every commit message with it. `"attribution": {"commit": ""}` in the settings turns this off.

The time does not include the preparation of the clone: in the IDE the repository is already there.
